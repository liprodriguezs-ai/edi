# Payment earmark subsystem (pinned-payment engine) — SHIPPED 2026-07-05, verified 2026-07-06

Generic seam so a payment can fund a specific domain entity (project contribution, amenity reservation) instead of flowing through FIFO.

- **Contract** `Modules/Collections/app/Contracts/PaymentEarmarkHandler.php`: `validateSubmission(array $data):void` (capture-time, BEFORE tx) + `resolveApplications(Payment $payment):array<{charge_id,apply_amount}>` (INSIDE confirm tx, payment row locked — creates/finds the destination charge, returns pinned applications).
- **Registry** `Support/PaymentEarmarkRegistry.php` (singleton bound in `CollectionsServiceProvider::register`): `register(type,class)`, `keys()` (drives controller `Rule::in`), `handlerFor(type)`. Consuming module registers its handler from ITS provider `boot()` — Collections NEVER imports the consumer.
- **Payment columns** (migration `2026_07_05_000000_add_earmark_columns_to_payment_table.php`): `earmark_type` string(100) nullable, `earmark_id` uuid nullable (both in `$fillable`, `filterableBy`). Partial unique index `payment_one_pending_per_earmark` (pgsql) on `(tenant_id,earmark_type,earmark_id) WHERE payment_status_id=PENDING_VALIDATION AND deleted_at IS NULL AND earmark_type IS NOT NULL` = race lock (≤1 pending report per earmark). `earmark_id` has NO exists-rule at controller — existence AND tenant scoping are 100% the handler's job (must use tenant-scoped Eloquent, never withoutGlobalScope).
- **PaymentService wiring**: `register()`/`submit()` call `handlerFor(type)->validateSubmission($data)` up-front (submit catches UniqueConstraintViolation → friendly 422). `register` (admin, CONFIRMED) + `validatePayment` (resident submit→CONFIRMED) call `resolveEarmarkApplications()` → handler `resolveApplications()` → feeds `applyManual()` (skips FIFO + credit). Earmark MUTUALLY EXCLUSIVE with `manual_applications`. Controller validation (register+submit): `earmark_type ['nullable','string','required_with:earmark_id', Rule::in(registry keys)]`, `earmark_id ['required_with:earmark_type','uuid']`. `submit()` persists cols only (charge born ONLY on validation — reject leaves zero residue).
- **Charge lifecycle of an earmark charge**: created PENDING (expected=payment amount, paid=0), then the pinned application makes paid==expected → `recomputeCharge` → COMPLETED. Born-completed ⇒ NEVER in `openChargesFor` (FIFO can't divert to/from it) ⇒ daily cron never ages it ⇒ never pollutes unit worst-wins / delinquency. This is WHY each confirmed payment gets its OWN fully-paid charge, not one partially-paid charge. (CAVEAT: reversing the payment re-opens the charge unless the consumer cancels it — see amenity S8 HIGH bug.)
- **Projects reference impl** (`Modules/Projects`): `Handlers/ContributionEarmarkHandler.php` (EARMARK_TYPE='project_contribution'), `Observers/ProjectChargeApplicationObserver.php` (created/updated/deleted → `ContributionService::syncFromChargeApplication(app,delta)` [SIGNED DELTA, not recompute], early-returns unless `charge->community_project_id`), charge link col via CONSUMER migration `Projects/.../add_community_project_id_to_charge_table.php` (nullable uuid + FK nullOnDelete). Registered in `ProjectsServiceProvider::boot()`. `ProjectActivationService::createChargeForUnit(project,unit,int):Charge` (:334) is the charge factory (disposable per-project concept `PROJ_{id}` + policy; policy only for by_share proration). `ChargeConceptCategory::idOfKey(KEY)` resolves category id; KEY_SERVICES='services', KEY_PROJECT='project'.
- **`PaymentService::cancel(Payment,string $reason):Payment`**: re-locks payment (throws if already cancelled), reverses applications (deletes rows → observer deleted-hook fires), restores/removes credit, decrements bank (confirmed only). Does NOT set `charge.is_cancelled` — a reversed earmark charge re-opens (see amenity S8 topic).
- **CONSOLIDATION**: `ContributionService::contribute()` LOST its `$paymentData` branch/param (money never enters it; board-only manual adjust remains); `POST /community-project/{id}/contribute` now 404(hidden)→validate(payment fields `prohibited`→422)→board gate; new `GET /community-project/{id}/contribution-payments` (?status=pending; non-board sees own units only). DirectChargeService = mostrador only (decision rule: existing domain entity → earmark; loose counter charge → DirectCharge).
