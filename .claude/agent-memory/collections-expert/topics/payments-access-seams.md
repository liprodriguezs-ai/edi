# Payments & access seams

- **Resident submit, no bank account** (2026-06-25): `POST /api/payment/submit` (`PaymentController::submit`) intentionally takes NO `bank_account_id` from residents; `SubmitPaymentSheet.tsx` has no "Cuenta destino". Backend: `bank_account_id` nullable → defaults to `BankAccount::where('is_active',true)->orderByDesc('is_primary')->first()`; 422 "El clúster no tiene una cuenta bancaria configurada." if none. Column is NOT NULL so defaulting keeps it populated. The default is applied in the CONTROLLER before calling the service. Admin `register` KEEPS it required.
- **Resident GET /payment/{id} access**: deep-link target for resident collection notifications; default ability `read.payment` (residents lack) → 403. Fix: `PaymentController::authorize()` override (NOT a Policy — project's `TraitController::authorize()` ignores `$arguments`). Orion `show()` fetches tenant entity FIRST (foreign→404), then `authorize('show',$entity)` passing the Payment INSTANCE (index/search/delinquency pass class STRING). Override relaxes only when `$ability==='read.payment' && $arguments instanceof Payment`: ownership via `UnitUser::where('unit_id',…)->where('user_id',…)->whereNull('end_date')->exists()`. FE `/payment/:id` gated `permissionEntity="payment_application"`; `/payment` list + `/delinquency` stay `"payment"`. Test `PaymentShowAccessTest.php`.
- **Rejected resident payment is TERMINAL — no resubmit/replace-image endpoint** (2026-07-19): `POST /payment/{id}/reject` (`PaymentController::reject` :283, `PaymentService::reject` :363) requires PENDING_VALIDATION, sets `payment_status_id=CANCELLED` + `cancellation_reason` (payment table migration `2026_05_31_154430` :29), NO charge/bank mutation (submit never applied FIFO, charges stay open). Resident is notified (`payment_rejected`, reason in body, click_action `/payment/{id}`; PaymentService :386-404) and sees the reason box on `PaymentDetailPage.tsx` :330-337 (label says "Motivo de cancelación", not "rechazo"). NO re-upload button for residents (action buttons gated `canManage=update.payment` :199/:272); only path = NEW `POST /payment/submit` from `StatementPage` → `SubmitPaymentSheet`. Admin dialog copy "podrá volver a subir su comprobante" (`PaymentActionDialogs.tsx` :68) means via a new submission. Requirement gap candidate: dedicated "corregir comprobante" flow.
- **/selects has NO permission gate** (security): `POST /api/selects` (`AngularController::selects`) resolves catalogs by key via `$mapper`, ZERO permission checks — returns ALL tenant rows (incl. `bank_account`) to ANY authed tenant user. Tenant isolation applies, ability gating does NOT. OPEN hardening: per-`read.<entity>` gate.
