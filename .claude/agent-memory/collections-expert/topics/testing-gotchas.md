# Testing gotchas (Collections backend)

- **Backend test discovery** (2026-06-30): `php artisan test --filter=X` does NOT find module tests — `phpunit.xml` registers only root `tests/Unit`+`tests/Feature`, NOT `Modules/*/tests`. Run BY PATH: `php artisan test Modules/Collections/tests/Feature/Services/Foo.php`. Many Collections/earmark feature tests actually live at ROOT `tests/Feature/Collections/`. Full `Modules/Collections/tests` dir is SLOW (>2min; ~3-13s/test from per-test seeding with `$connectionsToTransact=[]`) — run targeted files with a generous timeout. Host php (Postgres 127.0.0.1:5432), NOT sail.
- **Catalog-resolution flakiness**: Collections tests use `RefreshDatabase` with `$connectionsToTransact=[]` → writes COMMIT and accumulate across tests/invocations. `Tests\Support\Catalog::id($model,$name)` resolves tenant catalogs by name via `orderByDesc('id')` (UUID v7) assuming "current tenant last seeded" — order-sensitive. Symptom: `TargetResolver` returns 0 billable units. FIX between heavy sessions: `php artisan migrate:fresh --env=testing --force`. Robust fix: pass an explicit `$tenant` to `Catalog::id`.
- **`$connectionsToTransact=[]` + afterCommit**: because tests aren't wrapped in a test tx, `DB::afterCommit` / `ShouldQueueAfterCommit` fire on the REAL service commit — assertions on deferred side effects work as in prod.
