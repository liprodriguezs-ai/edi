# Direct charge / cargo puntual (cobro de mostrador)

## Phase 1 — SHIPPED 2026-07-03 (backend only; FE Phase 1 pending)
Atomic "create ad-hoc charge + cobra it in the same act", pinned so FIFO never diverts the money to old debt. Modeled on `ContributionService::contribute($paymentData)` minus the project link.
- **Endpoint** `POST /api/charge/direct` → `ChargeController::direct()` (custom route under `$customActionMiddleware`, next to `charge/{id}/cancel`). THIN: perms + validate + method gates → delegates to `DirectChargeService`. Perms: BOTH `create.charge` AND `create.payment` (or `*`) via `tokenCan`. 201 body `{data:{charge,payment}}`.
- **Request**: `unit_id`(req,uuid,exists tenant), `charge_concept_id`(nullable,uuid,exists, required_without concept_free_text), `concept_free_text`(nullable,≤255, required_without charge_concept_id), `expected_amount`(req,int 1..MoneyLimit), `payment_method_id`(req,exists), `bank_account_id`(req,uuid,exists tenant), `paid_at`/`issued_at`/`due_date`(nullable date, default today), `reference`≤255, `physical_receipt_number`≤100, `notes`≤2000, `receipt`(nullable pdf/jpg/jpeg/png/webp ≤10MB; REQUIRED for non-cash). Method-enabled + receipt gates run in controller (422) BEFORE the service.
- **`DirectChargeService::create(array): array{charge,payment}`**: ONE `DB::transaction` → (a) ad-hoc `Charge` (`charge_batch_id`/`charge_policy_id` null, `paid_amount` 0, `is_cancelled` false, `grace_days` 0 [explicit real 0, not null], status via `resolveStatusKey`, `description`=free text or null); (b) `PaymentService::register([... 'manual_applications'=>[['charge_id'=>$charge->id,'apply_amount'=>$expected]]])`. NEVER `applyUnitCreditFifo`. Manual apply path skips BOTH FIFO and credit-consumption.
- **"Otro" free-text path**: non-empty `concept_free_text` ⇒ resolve seeded `OTHER` concept (`ChargeConcept::where('code','OTHER')`, tenant-scoped) + store text in `charge.description`; else use `charge_concept_id`, description null. Missing OTHER → `InvalidArgumentException` → 422.
- **New column** `charge.description` (nullable string) — migration `2026_07_03_000001_add_description_to_charge_table.php`; in `Charge::$fillable` after `charge_concept_id`. Free-text motive; null for batch/catalog charges.
- **Shared concern** `Http/Controllers/Concerns/ResolvesPaymentMethodRules.php`: `requiresReceipt()` (non-cash needs comprobante; `PaymentMethod::CASH`) + `paymentMethodIsEnabled()` (`Setting collections.payment_methods_enabled` JSON; absent/empty ⇒ all allowed). Used by BOTH PaymentController and ChargeController.
- **Seeder** `TenantCatalogSeeder::seedDirectChargeConcepts()` (after CATALOGS loop): firstOrCreate category + 4 concepts firstOrCreate by code: `ACCESS_CARD_REPLACEMENT`, `HALL_RESERVATION`, `FINE`, `OTHER`. Idempotent by code. `charge_concept` is a business model (BelongsToTenant), NOT in declarative CATALOGS.
- **Tests** `tests/Feature/Collections/DirectChargeTest.php` (ROOT) — 8 green/32 assert: anti-FIFO CORE, Otro→OTHER+description, atomicity rollback, HTTP cash 201, transfer requires receipt 422, transfer+receipt 201, disabled method 422, missing create.charge 403.
- **GOTCHAS**: (1) near-duplicate categories (see round-2 fix); (2) NO backfill for existing tenants (see round-2 backfill command); (3) both concept_id AND free_text sent ⇒ free_text wins (round-2 makes them mutually exclusive); (4) FE Phase 1 not built — load catalogs LAZY.

## Architecture-review fixes — SHIPPED 2026-07-03 (round 2, NOT committed)
- **Receipt job commit-safe**: `GenerateReceiptPdfJob implements ShouldQueue, ShouldQueueAfterCommit`. Fixes REAL prod bug: nested `register()` (DirectCharge/Contribution) dispatches at transactionLevel≥1 while OUTER tx open → async worker could run before commit → `Payment::find()` null → PDF+email silently dropped. Now deferred to OUTERMOST commit. SAFE: no test asserts `assertPushed`; DataImport uses `register(..., silent:true)` (no dispatch); tests use `$connectionsToTransact=[]` so afterCommit fires on the REAL service commit.
- **concept_id vs free_text mutually exclusive**: `ChargeController::direct()` adds `'prohibits:charge_concept_id'` to `concept_free_text` (+ inline Spanish msg — there is NO `lang/es/validation.php`). `validateProhibits` is `validateRequired`-GATED: only fires when field is present-AND-non-empty → sending `concept_free_text:''/null` alongside real `charge_concept_id` NOT wrongly rejected. Test `test_both_concept_id_and_free_text_is_rejected`.
- **201 over-fetch removed**: `direct()` returns `$result['charge']`/`['payment']` AS-IS. register() already eager-loads applications/payment_status/payment_method in-tx.
- **Backfill command** `collections:backfill-direct-charge-concepts` (`Console/Commands/BackfillDirectChargeConceptsCommand.php`, registered in `CollectionsServiceProvider::registerCommands`): loops `Tenant::all()` → `$tenant->run(fn () => (new TenantCatalogSeeder)->seedDirectChargeConcepts())`. Idempotent. `seedDirectChargeConcepts()` now PUBLIC. Run once per deploy for pre-2026-07-03 tenants.
- **Category consolidated + protected**: removed bare `['name'=>'Servicio','order'=>3]` from `TenantCatalogSeeder::CATALOGS`. Direct-charge category `Servicios / Eventuales` now carries `key = ChargeConceptCategory::KEY_SERVICES ('services')` → HasCatalogKey protects (undeletable, key immutable). Seeder/backfill stamp the key on pre-existing keyless rows via `saveQuietly()` (HasCatalogKey `updating` guard reverts a `key` change on a normal save). Existing tenants may keep an orphan empty `Servicio` (harmless, admin-removable).
- **OTHER concept undeletable**: `ChargeConcept::PROTECTED_CODES = ['OTHER']` + `booted()` `deleting` guard throws ValidationException (keyed on `code`; charge_concept has NO `key` column). `code` still editable via ChargeConceptUpdateRequest (secondary risk, open). Presets stay admin-removable by design.
- **Constructor injection**: `DirectChargeService` promoted `readonly` ctor (`ChargeStatusService`, `PaymentService`) instead of `app(...)`.
