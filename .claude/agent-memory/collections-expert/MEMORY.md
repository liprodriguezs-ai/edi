- **Services** (`app/Services/`): `AmountCalculator` (amount per unit), `TargetResolver` (units a batch hits), `ChargeGenerationService` (batch→charges), `ChargeStatusService` (FSM + unit worst-wins rollup), `PaymentService` (register/submit + FIFO), `ChargePolicyService`, `CollectionsReportService` (aging), `PeriodicityScheduleResolver`+`PeriodRun`. - **Cron**: `RefreshChargeStatusesCommand` daily `dailyAt('01:00')` → `ChargeStatusService::refreshAllOpenCharges` (temporal `pending→due_soon→overdue`; selects `charge_status_id ∈ {PENDING,DUE_SOON,PARTIAL,OVERDUE} AND is_cancelled=false`). `GenerateMonthlyChargesCommand` (uses `collections.charge_generation_day`).
- **Periodicity: SÓLO 4 filas sembradas (2026-07-26, decisión del dueño)** — `MONTHLY`, `YEARLY`, `EVENTUAL`, `EVERY_TWO_DAYS`. `BIMONTHLY`/`WEEKLY`/`BIWEEKLY` quedan **comentadas** en `CatalogSeeder::seedPeriodicities()` (`database/seeders/CatalogSeeder.php` ~líneas 273/276/277). - **Money**: ALWAYS bigInteger minor units (cents), cast `MoneyIntegerCast` (services) / `TenantMoneyCast` (API boundary). Never decimal/float.
- **Catalogs split**: FSM states CENTRAL (`charge_status`,`payment_status`,`charge_batch_status` — fixed UUIDs, `CatalogSeeder`); label catalogs TENANT-SCOPED (`charge_concept_category` — `TenantCatalogSeeder`). Behavior selectors `amount_mode`,`periodicity`,`payment_method`,`surcharge_mode` are central.
- **FIFO order**: credit_balance first, then open charges by `due_date` ASC, `issued_at` ASC, `id` ASC. `openChargesFor` = `is_cancelled=false AND paid_amount < (expected − discount + surcharge)`, row-locked.
- **worstWins priority** (`ChargeStatusService`): OVERDUE 0 > PARTIAL 1 > DUE_SOON 2 > OVERPAID 3 > COMPLETED 4 > PENDING 5. `resolveStatusId(x)` is identity; ChargeStatus constants ARE the central UUIDs.
- **Orion tx boundary**: `orion.transactions.enabled=true` wraps STANDARD ops (store/update/destroy/restore/batch); custom routes are NOT wrapped → must own `DB::transaction()`. `register/submit/validate/cancel` (custom) keep their own tx.
- **Delinquency xlsx export (2026-07-19)**: `GET /delinquency/report` → `PaymentController::delinquencyReport`, gated `report.payment`; shares `CollectionsReportService::delinquencyByUnit()` with `GET /delinquency` (single source of the outstanding formula — never duplicate it). Uses core `ReportExport` + `Excel::download('morosidad.xlsx')`; money cells `(float) TenantMoney::make($minor)->formatByDecimal()` (project xlsx rule, never /100). Test: `tests/Feature/Collections/DelinquencyReportExportTest.php`. FE: `PaymentResource.delinquencyReport()` blob + local `isExporting` button on `DelinquencyPage.tsx` (canonical non-useBaseList export precedent alongside `useContributionsList.exportXlsx`).
- **Delinquency server-side filters (2026-07-19)**: `GET /delinquency` + `/delinquency/report` accept `search` (combined: unit number/type-label/tower OR ACTIVE resident name via `unit.unitUsers.user`, `end_date IS NULL`; `LOWER(...) LIKE`, portable, never ILIKE), `charge_concept_ids[]` (CHARGE-level → row outstanding/charge_count reflect only those concepts), `min_months_overdue` (row-level: `oldest_due_date <= today − N months` via `subMonthsNoOverflow` + direct date compare — never diffInDays), `min_amount`/`max_amount` (minor units, on aggregated outstanding; deliberately NO cross-field min<=max rule → min>max yields empty, parity with Orion range filters). Controller keeps ONLY `validateDelinquencyFilters()` (HTTP validation); the aggregation lives in `CollectionsReportService::delinquencyByUnit(array $filters)` — pure SQL `GROUP BY unit_id` + `HAVING` (amounts + months), then ONE `Unit::with(unitType,tower)` lookup for `full_identifier` → O(units) not O(charges). KPIs AND export reflect the filtered set. **Outstanding formula is centralized in `Charge::outstandingSqlExpression()`** (GREATEST/COALESCE SQL, parity-documented vs `ChargeStatusService::effectiveExpected()`), consumed by delinquencyByUnit AND computeAging (selectRaw column) — never re-derive it inline (PHP copy still exists in `PaymentController::cachedStatementAggregate`, candidate to converge). FE: `DelinquencyPage` filters are server-side (single 350ms debounce over the whole params object, `placeholderData: keepPreviousData`), concepts lazy via `useLazyCatalogs(CHARGE_CONCEPT)`. Test: `tests/Feature/Collections/DelinquencyFilterTest.php`. FIXTURE GOTCHAS: `charge_policy_active_unique` (one ACTIVE policy per tenant+concept+periodicity) and `charge_batch_period_unique` (only `WHERE month IS NOT NULL`) — reuse the policy per concept and set `month=null` (eventual) when a test needs several batches of one policy.

Fix: signed value; `avg_days_overdue` counts only `daysPastDue>0` in num+denom. Test `CollectionsReportControllerTest::test_avg_days_overdue_not_diluted_by_not_yet_due_partial`.
