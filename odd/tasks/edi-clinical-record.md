# EDI as a clinical record (agenda + child record)

Objective: reorient the app as a medical-record system: the agenda is the daily entry point and the Prueba EDI lives inside each child's record.
Branch: `main` working tree, NO commits (same directive as the other features in this tree). Delivery: 3 deliveries (agenda → record → menu), each testable alone. Test runners: frontend `tsc` + `vitest` + `pnpm build`; backend PHPUnit only if backend changes.

## Specs

- **S1 — Agenda views.** "se puede ver qué agendar hay el día de hoy … debe tener vista semanal y mensual, y un modo lista". Views: Día (one column per practitioner, existing), Semana (existing), **Mes** (new), **Lista** (new, grouped by day with each appointment's status and its next action). Opens on today.
- **S2 — Today at a glance.** The agenda shows today's counts (citas, atendidas, en sala de espera, Pruebas EDI por aplicar) next to the existing waiting room. Source: approved visual proposal (artifact QrV5qrVGFnKcWSWEUD1BPE).
- **S3 — Agenda is home.** After login a clinical user lands on `/agenda` instead of the template's role routes (platform super-admin keeps its own destination). Assumption: "clinical user" = anyone with `read.appointment` who is not super-admin.
- **S4 — Child record with tests.** "cuando entre al expediente del paciente/niño debe haber una sección para ver las pruebas y ahí toda la funcionalidad que ya tienes". Record tabs gain Resumen and Pruebas EDI; "Nueva Prueba EDI" creates today's visit; screening screens link back to the record.
- **S5 — Menu.** "debe de ser como un sistema de expediente médico, ese debe de ser el enfoque". Menu: Agenda, Niños, Seguimientos, Estimulación, Reportes, Configuración; global Prueba EDI and Visitas lists leave the main menu (approved: "si dale").
