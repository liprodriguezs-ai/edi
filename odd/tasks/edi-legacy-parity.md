# EDI legacy parity (Prueba EDI, a elección, láminas, reportes, estado nutricional)

Objective: bring back the legacy EDI screens the user relies on (`/Users/rodriguez/code/edi-backend`, Zend) that the rebuild left out, keeping the legacy titles.
Branch: `main` working tree, NO commits (same directive as edi-agenda / tenant-timezone-utc; 557 pre-existing uncommitted files). Test runners: backend PHPUnit (host PHP, test DB 5451), frontend `tsc` + `vitest` + `pnpm build`.

## Specs

- **S1 — Keep legacy titles.** User: "por fa no cambiemos los titulos podemos dejarlo como prueba edi". The screening module is shown to users as **"Prueba EDI"** (menu, page titles, buttons, breadcrumbs, PDF), not "Tamizaje(s)". Identifiers stay in English (`screening`).
- **S2 — Prueba EDI a elección.** User: "si debemos de tener prueba edi a eleccion". Legacy `/pruebaedi`: the evaluator picks the group to apply ("Evaluación a realizar") from all age groups instead of the age-derived one. New: when starting a Prueba EDI the evaluator may choose any age group of the active instrument version; the server persists the chosen group and the selection mode (`age` | `chosen`), scores with THAT group's rules, and rescoring keeps it. Result still computed server-side (invariant 1). Assumption: the child's real age (and corrected age) is still computed from the birth date; the legacy free-typed age is NOT copied (it overwrote the folio age and was falsifiable).
- **S3 — Láminas.** User: "las laminas". Legacy shows buttons "Lámina A", "Lámina B", "Lámina C", "Lámina D" and "Manual" at the top of the Prueba EDI; each opens the image/PDF in a new tab. Assets copied from `edi-backend/public/formatos_fua_edi/herramientas/LaminaA..D.jpeg` and `ManualEDI2aEdicion.pdf`. The per-group "Material" text is shown for the applied group when the instrument has it.
- **S4 — Reportes.** User: "los reportes". (a) **Concentrado EDI** page: table of the latest + previous Prueba EDI per child of the center (legacy columns: child, birth date, age, SDG, edad corregida, previous/last date + result + axes with impact, nutritional status, caregiver, next evaluation), Excel export. (b) **Reporte general** page (legacy `/censos/ninosano`, "censo de menores de 5"): per child — birth date, age, last measurement date, weight/height, P/T, P/E, T/E, caregiver, previous and last EDI date + result; Excel export. Filter by health center (tenant scope). Anemia/consulta columns from legacy are NOT available in the new domain → omitted (assumption).
- **S5 — Estado nutricional.** User: "y el estado nutricional". Server classifies weight-for-height, weight-for-age and height-for-age for children 0–60 months using the WHO tables migrated from legacy (`cat_peso_talla`, `cat_peso_edad`, `cat_talla_edad`), stored in grams/mm (hard rule 7). Bands (NOM-031-SSA2-1999, assumption — legacy shifted the bands by 1 SD, labelling every child below the median "desnutrición leve"): P/T and P/E — ≤ −3 SD "Desnutrición grave", (−3,−2] "Desnutrición moderada", (−2,−1] "Desnutrición leve", (−1,+1) "Peso normal", [+1,+2) "Sobrepeso", ≥ +2 "Obesidad"; T/E — ≤ −2 SD "Talla baja", (−2,−1] "Talla ligeramente baja", (−1,+1) "Talla normal", [+1,+2) "Talla ligeramente alta", ≥ +2 "Talla alta". Length/height tables: 0–23 months vs 24–60 months; height rounded to the nearest 0.5 cm (legacy truncated with `intval`, so .5 heights found no row). Out of table range → "Sin referencia". Visible in Prueba EDI (capture + detail + PDF), as its own "Estado nutricional" screen in the child record (history + capture), and in both reports.
- **S6 — Edad corregida visible.** User: "no veo las cosas que habia en el otro lado, no se Lo de edad corregida". Legacy had a standalone "Edad corregida" calculator in the menu. New: same calculator page (birth date + SDG → corrected age, explanation), using the same server rule as the Prueba EDI (< 37 weeks, < 24 months).
- **S7 — Grupo etario visible.** User: "no veo el grupo etario". Prueba EDI shows "Grupo N" (and its age range) prominently while applying and in the detail/PDF, as legacy did.
