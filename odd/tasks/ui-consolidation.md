# UI consolidation sweep (componentize repeated UI)

Objective: find UI pieces that are hand-rolled, duplicated or inconsistent across `frontend/src/modules/**` and replace them with ONE shared component each.
Branch: `main` working tree, NO commits (same directive as previous features; many pre-existing uncommitted files). Delivery: single working-tree change. Test runner: frontend `tsc -p tsconfig.app.json --noEmit` + `vitest run` + `pnpm build` + `pnpm lint`.

## Specs

- **S1 — Sweep and componentize.** User: "veo cosas de ui diferentes, quiero que analices y quioero que cosas similares comopoentices, necesito que hagas un barrido, por fa". Every pattern found in the sweep (inventory in L2) is migrated to a single shared component, reusing existing shared atoms first (`StatusPill`, `PageHeader`, `Modal`, `ConfirmDialog`, `EntityNotFound`, `KpiTile`, `Callout`) and creating new ones only where none exists. Scope is the whole app, not one screen; any site left out is reported with a reason.
- **S2 — Modal rule.** User chose "Mixto por tipo (Recomendado)": "Formularios de captura/edición → panel lateral (Modal compartido). Confirmaciones cortas (cancelar, invalidar, re-puntuar, con motivo opcional) → diálogo centrado (ConfirmDialog con espacio para campos)."
- **S3 — Clinical semaphore.** (Derived from S1, assumption.) The EDI result color (green/yellow/red) renders through ONE component (`ResultColorPill`, built on `StatusPill` tones g/y/r and theme tokens), replacing `SemaphoreBadge` and `resultColorBadge`. Non-clinical statuses (active/inactive, yes/no, tenant status) never use g/y/r tones (per `StatusPill` doc): use `b`/`n`, or `y`/`r` only for warning/danger states that are not clinical results (assumption: tenant "suspended"/"expired" keep a warning/danger meaning).
- **S4 — No behavior change.** Pure presentation refactor: same data, same handlers, same Spanish copy (except unifying loading/empty copy), same permissions. UI text stays Spanish (hard rule 2), no `any`.
