# Design: EDI Appointment Scheduling

Change: `edi-appointment-scheduling`

## 1. Context

`visit` today is a completed encounter: server-generated immutable folio `V-YYYY-NNNNNN` (`VisitService::nextReceiptNumber()` under `lockForUpdate` against `visit_receipt_sequence`), date-only `visit_date` validated `before_or_equal:today` in `VisitCreateRequest` (plus a birth-date guard), no time, no status. The existing partial unique `visit_tenant_receipt_unique ON visit (tenant_id, receipt_number) WHERE deleted_at IS NULL` is NULL-tolerant (Postgres treats each NULL as distinct). `FollowUp` is the delivered mold for everything this change adds: `FollowUpLifecycleService` (transaction + `lockForUpdate` + `assertOpen` frozen-precedence + `forceFill`), `FollowUpStatus` (central catalog, fixed UUIDs), `FollowUpDomainException` (self-rendering, `ShouldntReport`), `RefreshOverdueFollowUpsCommand` (convergent per-tenant cron), `notifyEvent` (afterCommit). Schedule-X 4.6.0 (`calendar`, `react`, `theme-default`) is installed and `index.css` already carries a marked `.sx__calendar-wrapper` block retargeting `--sx-color-primary` to the EDI indigo (`#3a48d8`). House patterns apply throughout: tenant tables via `BaseModel::columns($table, true)`, catalog FKs as bare `uuid()->index()` (no DB FK), partial uniques via `DB::statement`, no PHP enums, guarded writes (fillable + FormRequest + service `forceFill`).

## 2. Decisions

| # | Decision | Rationale |
|---|---|---|
| D1 | An appointment IS a `visit` born `scheduled` — additive columns on the existing entity, no new module or table for appointments | The clinical flow is one lifecycle (schedule → attend → screening hangs from the same row); a separate `appointment` table would force a fragile promote-on-attend copy step and duplicate child/practitioner/center columns. Rejected: separate `Appointment` module (user fixed "extend `visit`" in the plan round). Mitigations for the overloaded semantics: `visit_status` is the single source of truth; `scheduled_at` (appointment moment) and `visit_date` (encounter date) are exclusive-by-state; the invariants live in `->comment()` on every new column |
| D2 | Folio at ATTEND, not at schedule: `receipt_number` and `visit_date` become `nullable()->change()`; `attend` fixes `visit_date`, stamps `attended_at`, and calls the extracted public `VisitService::assignReceiptNumber($visit, $year)`. `visit_tenant_receipt_unique` is NOT touched — N unattended NULL folios coexist under it. `VisitCreateRequest` keeps `before_or_equal:today` + birth-date guard verbatim (walk-in contract intact); `VisitAttendRequest` replicates both for the attend path; `VisitScheduleRequest` validates `scheduled_at` `after:now` | The official sequence must never burn numbers on cancelled/no-show appointments (gap-free folio is the audit contract from REQ-CH-008). Rejected: folio at schedule + void on cancel (creates gaps or a parallel voided-folio ledger); rejected: separate appointment folio (two numbering systems for one entity). NULL coexistence is free because Postgres partial b-tree uniques treat NULLs as distinct |
| D3 | New CENTRAL FSM catalog `visit_status` (mold `follow_up_status`): `CentralCatalogModel`, `key/name/sort_order`, fixed UUID consts `VisitStatus::SCHEDULED/CONFIRMED/ATTENDED/CANCELLED/NO_SHOW = ed600001-0000-4000-8000-000000000001..0005`, seeded by `CatalogSeeder::seedVisitStatuses()`. Terminals `attended/cancelled/no_show` answer 409 `VISIT_FROZEN` with precedence over `INVALID_STATUS_TRANSITION` (identical `assertOpen`-first ordering as FollowUp) | Hard rule 4: the backend branches on these rows (FSM) → central, fixed UUIDs, read-only for tenant roles. Rejected: tenant-scoped status (admins must not rename/delete states code branches on); rejected: string column (breaks the catalog-FK house pattern and the selects pipeline) |
| D4 | Availability = two tenant-scoped tables in `Modules/Clinic`: `practitioner_schedule` (weekly working hours: `practitioner_id`, `health_center_id`, `weekday` 0–6, `start_time`, `end_time`, `slot_duration_minutes`, `is_active`) + `practitioner_schedule_exception` (per-date `block`/`open` windows with nullable times = whole day). Weekday convention is Carbon `dayOfWeek` (0=Sunday … 6=Saturday), fixed in the column `->comment()` | Weekly template + date exceptions is the minimal model that answers "when can this practitioner be booked" without recurring-rule complexity (RRULE rejected as out-of-scope machinery). Multiple rows per weekday allowed (split shifts). Clinic owns them because availability is a property of the practitioner (Clinic domain), not of the visit |
| D5 | Slots and clash: `AvailabilityService::availableSlots(practitionerId, date)` = weekday windows sliced by `slot_duration_minutes` − `block` exceptions + `open` exceptions − active (`scheduled\|confirmed`) overlapping appointments − past slots when date = today. Anti-double-booking is two layers: (a) partial unique `visit_practitioner_slot_unique ON visit (tenant_id, practitioner_id, scheduled_at) WHERE deleted_at IS NULL AND scheduled_at IS NOT NULL AND visit_status_id IN (SCHEDULED, CONFIRMED)` for the exact-start race; (b) `AvailabilityService::assertNoClash(...)` inside the same transaction — `lockForUpdate` on the practitioner's active appointments in a bounding window, overlap computed against per-row duration, throws 409 `APPOINTMENT_CLASH`. Booking OUTSIDE the weekly schedule is allowed (availability informs the picker; only real overlap blocks) | `EXCLUDE USING gist` on a tstzrange would be the textbook constraint but is rejected deliberately: it needs the `btree_gist` extension for the tenant/practitioner equality columns, adds a migration/extension surface with zero precedent in this codebase, and the house style is partial b-tree uniques + transactional guards (QuotaService, VisitService, FollowUp all serialize this way). The per-practitioner lock window is tiny, so the guard is cheap. Allowing out-of-schedule booking keeps the admin in control (overbooking, house calls) without a bypass flag |
| D6 | `VisitLifecycleService` (`Modules/ChildRecord/app/Services/`, mold `FollowUpLifecycleService` verbatim): `schedule`, `confirm`, `reschedule`, `cancel(reason)`, `noShow`, `attend` — each `DB::transaction` + `lockForUpdate` re-read + `assertOpen` (frozen first) + transition check + `forceFill`. `attend` sets `visit_date`/`attended_at` + folio via `VisitService::assignReceiptNumber()`; `schedule`/`reschedule` run `assertNoClash`; `reschedule` copies old `scheduled_at` → `rescheduled_from_at`, increments `reschedule_count`, resets status to `scheduled`. New `VisitDomainException` (mold `FollowUpDomainException`): `frozen()` → 409 `VISIT_FROZEN`, `invalidStatusTransition()` → 409, `clash()` → 409 `APPOINTMENT_CLASH`. Lifecycle columns (`visit_status_id`, all stamps) excluded from `$fillable` — service `forceFill` only | Same guarded-writes stack that made screening results and follow-up statuses unforgeable. Rejected: FSM inside Orion `update` payloads (whitelist erosion, no per-transition validation); rejected: model events/observers for transitions (implicit, untestable ordering) |
| D7 | API surface: keep `Orion::resource('visit')` and the walk-in `performStore` → `VisitService::create()` path byte-compatible (walk-in now also stamps `ATTENDED` + `attended_at` via `forceFill` — born attended, folio at create, exactly as today). FSM actions are custom `Route::post` lines: `visit/schedule` (`create.visit`), `visit/{visit}/confirm\|reschedule\|cancel\|no_show` (`update.visit`), `visit/{visit}/attend` (NEW fine permission `attend.visit`). Requests: `VisitScheduleRequest`, `VisitRescheduleRequest`, `VisitCancelRequest` (reason required), `VisitAttendRequest`. `VisitController`: `includes()` += `visit_status`, `cancelled_by_user` (with `withoutGlobalScope(UserTenantScope::class)`); `filterableBy()` += `visit_status_id`, `scheduled_at`; `sortableBy()` += `scheduled_at`. Clinic: `Orion::resource('practitioner_schedule')` + `Orion::resource('practitioner_schedule_exception')` — BOTH under `$keyForPermission = 'practitioner_schedule'` — plus `GET practitioner/{practitioner}/slots?date=` (`read.practitioner_schedule`) | Custom actions per house §2.10 (explicit verbs, `response()->json(['message','data'])`, never named `dispatch`). `attend.visit` is a separate permission because attending mints the folio and unlocks the clinical screening — clinical authority, not agenda authority. One permission family for both availability tables keeps the assistant matrix simple (read both, write neither) |
| D8 | Reminders: `SendAppointmentRemindersCommand` (`appointment:send-reminders`, mold `RefreshOverdueFollowUpsCommand`): per tenant, select `scheduled\|confirmed` visits with `reminder_sent_at IS NULL AND scheduled_at > now() AND scheduled_at <= now() + lead`, fire `notifyEvent('appointment.reminder')`, stamp `reminder_sent_at` in the same transaction. Lead time from `config('childrecord.appointment_reminder_lead_hours')` (default 24). `Schedule::command(...)->hourly()` in `routes/console.php` | Convergent window (`<= now + lead`, not a narrow band) means a missed hourly run self-heals on the next tick; the stamp makes reruns no-ops (same idempotence argument as follow-up D7). Rejected: queued per-appointment delayed jobs (reschedule/cancel would need job revocation plumbing) |
| D9 | Notifications: 4 new `NotificationEvent` rows with fixed UUIDs `ed600002-0000-4000-8000-000000000001..0004` — `appointment.created`, `appointment.rescheduled`, `appointment.cancelled`, `appointment.reminder` — new `NotificationCategory::APPOINTMENT = 'appointment'`, `audience = 'board'`, `supports_email = false`, `supports_push = true`, `supports_whatsapp = false`, `default_channels = ['log','firebase_push']`, seeded in `CatalogSeeder::seedNotificationEvents()`. Recipients: the appointment's practitioner user + `userIdsWithRole` for `administrator` and `assistant`. Fired from `VisitLifecycleService` via `notifyEvent` (afterCommit) | Literal reuse of the verified engine (settings fallback to `default_channels`, unknown keys suppressed) — no new channel. Caregiver SMS/WhatsApp/email is explicitly out of scope: recipients are login users; the caregiver has no account. Email deferred for the same React Email pipeline cost as follow-up D8 |
| D10 | Role `assistant`: `csv/roles.csv` row; `Role.php` consts `ASSISTANT = '1a2b3c4d-000b-0000-0000-000000000011'` + `SLUG_ASSISTANT = 'assistant'` appended to `ORGANIZATION_SLUGS`; `RolePermissionTableSeeder` block = `read.{child, health_center, practitioner_profile, visit, visit_status, practitioner_schedule}` + `create.visit`, `update.visit`, `report.visit` — deliberately NO `attend.visit`, NO `practitioner_schedule` writes, NO `delete.visit`. `visit_status` appended to `$centralCatalogs`. `administrator` receives every non-exclusive permission including `attend.visit` — today there is NO separate "professional" role: the practitioner operates as `administrator`, which already schedules AND attends | Front-desk staff run the agenda without clinical powers (attend mints folio + opens screening) and without touching the practitioners' working hours. Scope is permission-based across the whole tenant, not ownership-based (assumption A5). Rejected: creating a `professional` role in this change — it would be a permissions redesign orthogonal to scheduling; noted for a future permissions pass |
| D11 | Registration (AGENTS.md rule 9, full checklist): `modules.csv` rows `Agenda` + `Disponibilidad` (next free ids in the `ed0000XX` sequence; same menu group as the existing Visitas/Clinic rows — verify exact group + free ids at apply); `permissions.csv` = 1 row `attend.visit` + 6 rows `practitioner_schedule`; `module_system.csv` 2 rows; `SystemTableSeeder` 5 maps — entities `'Agenda' => 'visit'`, `'Disponibilidad' => 'update:practitioner_schedule'` (the ChildRecord catalog-page prefix pattern so only writers see the menu row), routes `'/appointment'`, `'/availability'`, calendar icon (verify name exists in `iconMap.ts`); `AngularController::$mapperSelects` += `'VisitStatus'`, `'PractitionerSchedule'`; `useCatalogs.ts::CatalogType` += `VISIT_STATUS`, `PRACTITIONER_SCHEDULE`. No new nwidart module → `modules_statuses.json` untouched | The `$mapperSelects`/`CatalogType` pair is string-coupled via `Str::studly` and fails SILENTLY (empty dropdown), so it ships atomically with the UI that consumes it (same lesson as follow-up D13). Menu rows come from `/api/menu`, so the assistant sees Agenda purely through `read.visit` — zero `ERoleUserSlug` edits |
| D12 | Frontend: new `modules/appointment/` as a CUSTOM surface (mold `ScreeningApplyPage` — no `useBaseCrud`): `AppointmentCalendarPage` + `useAppointmentCalendar` (`@schedule-x/react` `useCalendarApp`, day/week/month views, events service, TanStack Query keyed by visible range via `POST /visit/search` with `scheduled_at` range filters + includes); `services/AppointmentResource.ts` = `createCrudApi` over `/visit` with `customMethods` `schedule/confirm/reschedule/cancel/noShow/attend/slots/agenda` (existing `VisitResource` untouched for the worklist); `utils/scheduleXAdapter.ts` centralizes UTC ISO ↔ Schedule-X local `'YYYY-MM-DD HH:mm'` (date-fns) and maps `visit_status.key` → Schedule-X calendar/color. Appointment status colors use indigo/neutral tones ONLY — the g/y/r semaphore stays reserved for clinical results (per `StatusPill` contract). New `modules/availability/AvailabilityConfigPage` (custom weekly editor per practitioner+center: 7 days × active/start/end/slot-duration + date blocks) with `ScheduleResource`/`ScheduleExceptionResource`. Routes in `App.tsx`: `/appointment` gated by `visit`, `/availability` gated by the `practitioner_schedule` write convention (mirror the existing catalog-page route gating at apply). Gating is 100% permission-based | Calendar + slot picker + lifecycle actions is exactly the "custom-logic screen" case §2.11 excludes from `CatalogCrudModule`. The native DnD plugin exists, is version-locked to the calendar, and `@dnd-kit` has no precedent here. The versioned `sx__*` class risk is contained by the single marked override block (one place to audit on bumps) + live visual verification |

The screening gate closes the one semantic hole D1 opens (screening ⇸ unattended visit). `down()` restores NOT NULL safely once unattended rows are pruned — every historic row carries folio + date |

## 3. Data model (definitive)

All new/altered columns carry `->comment()`; tenant tables use `$table->comment(...)` first line + `BaseModel::columns($table, true)`; catalog/user FKs are bare `uuid()->index()`.

**ALTER `visit`** (`Modules/ChildRecord/database/migrations/..._add_appointment_fields_to_visit_table.php`)

| Column | Type | Constraints | Comment (invariant) |
|---|---|---|---|
| `scheduled_at` | timestampTz | nullable | Scheduled appointment start (UTC); NULL on walk-in/historic attended rows |
| `duration_minutes` | smallInteger | nullable | Appointment length; defaults from practitioner_schedule.slot_duration_minutes at scheduling |
| `visit_status_id` | uuid, index | nullable → backfill → NOT NULL | FK to central visit_status; service-derived via lifecycle, never client-writable |
| `confirmed_at` | timestamp | nullable | Moment the appointment was confirmed |
| `attended_at` | timestamp | nullable | Moment attend ran; visit_date + receipt_number are set in the same transaction |
| `cancelled_at` | timestamp | nullable | Moment of cancellation |
| `cancellation_reason` | text | nullable | Mandatory reason captured on cancel |
| `cancelled_by_user_id` | uuid | nullable | FK to user who cancelled |
| `reschedule_count` | smallInteger | default 0 | Times this appointment was rescheduled (uncapped, counted only) |
| `rescheduled_from_at` | timestampTz | nullable | Previous scheduled_at before the last reschedule |
| `reminder_sent_at` | timestamp | nullable | Idempotency stamp for appointment:send-reminders |

Alters: `receipt_number` + `visit_date` → `nullable()->change()` (D2). Backfill (D13). New indexes: `(tenant_id, practitioner_id, scheduled_at)`, `(tenant_id, visit_status_id, scheduled_at)`, and the D5 partial unique `visit_practitioner_slot_unique`.

**`practitioner_schedule`** (Clinic) — 'Weekly working-hours template of a practitioner at a health center'

`practitioner_id` uuid idx NOT NULL — FK to practitioner_profile · `health_center_id` uuid idx NOT NULL — FK to health_center · `weekday` smallint NOT NULL — 0=Sunday…6=Saturday (Carbon dayOfWeek) · `start_time`/`end_time` time NOT NULL — local clinic time · `slot_duration_minutes` smallint NOT NULL — slot granularity for this window · `is_active` boolean default true. Partial unique `(tenant_id, practitioner_id, weekday, start_time) WHERE deleted_at IS NULL`.

**`practitioner_schedule_exception`** (Clinic) — 'Per-date availability override: block (vacation/absence) or open (extra window)'

`practitioner_id` uuid idx NOT NULL · `date` date NOT NULL · `type` string NOT NULL — 'block'\|'open' (class constants + TYPES array, no PHP enum) · `start_time`/`end_time` time nullable — NULL pair = whole day · `reason` string nullable. Index `(tenant_id, practitioner_id, date)`.

**Central catalog `visit_status`** (`CatalogSeeder::seedVisitStatuses()`): scheduled/Agendada 1 · confirmed/Confirmada 2 · attended/Atendida 3 · cancelled/Cancelada 4 · no_show/No asistió 5 — consts `ed600001-0000-4000-8000-000000000001..0005`.

## 4. FSM

| From | schedule | confirm | reschedule | cancel | noShow | attend |
|---|---|---|---|---|---|---|
| *(new)* | → scheduled | — | — | — | — | *(walk-in create → attended + folio)* |
| scheduled | — | → confirmed | → scheduled (count++) | → cancelled | → no_show | → attended |
| confirmed | — | — | → scheduled (count++) | → cancelled | → no_show | → attended |
| attended / cancelled / no_show | 409 `VISIT_FROZEN` on every action (precedence over `INVALID_STATUS_TRANSITION`) | | | | | |

`attend` = fix `visit_date` (≤ today, birth-date guard), stamp `attended_at`, assign folio, status → attended. `no_show` is manual (A3).

Slot algorithm (D5): windows(weekday, active) sliced by `slot_duration_minutes` → subtract `block` exceptions → add `open` exception windows (sliced with the practitioner's smallest active `slot_duration_minutes`; fallback constant 30) → subtract overlapping `scheduled|confirmed` appointments (per-row duration) → drop past slots when date = today. Domain error codes: `VISIT_FROZEN` (409), `INVALID_STATUS_TRANSITION` (409), `APPOINTMENT_CLASH` (409) — Spanish messages, stable codes.

## 8. Assumptions (encode → correct before apply)

| # | Assumption | Default encoded |
