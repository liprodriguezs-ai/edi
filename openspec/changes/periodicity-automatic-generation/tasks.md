## Phase 2 — `PeriodicityScheduleResolver` Service

- [x] 2.1 **[RED]** Write unit tests for `PeriodicityScheduleResolver::runsForToday()`. File: `Modules/Collections/tests/Unit/Services/PeriodicityScheduleResolverTest.php`. Cover:
  - MONTHLY: fires only on `generationDay`; `PeriodRun` has `cycle=null`, `dueDate=issued+15d`.
  - BIMONTHLY: fires only on `generationDay` in odd months (Jan/Mar/May/Jul/Sep/Nov); skips even months.
  - YEARLY: fires only on `generationDay` in January; skips all other months.
  - WEEKLY: fires only on Monday (`dayOfWeekIso===1`); `cycle=isoWeek`; `dueDate=issued+7d`; non-Monday → empty.
  - BIWEEKLY: fires on day 15 (`cycle=1`, `dueDate=issued+15d`) AND last day of month (`cycle=2`); other days → empty.
  - Sc 6 (Feb EoM): Feb 28 non-leap → cycle 2; Feb 29 leap year → cycle 2; no Feb-30/31 hazard.
  - Distinct cycles: fortnight-1 and fortnight-2 in same month return separate `PeriodRun` on their respective trigger days.
- [x] 2.2 Create `Modules/Collections/app/Services/PeriodRun.php`: `final readonly class PeriodRun { public function __construct(public int $year, public ?int $month, public ?int $cycle, public string $periodLabel, public Carbon $issuedAt, public Carbon $dueDate) {} }`.
- [x] 2.3 **[GREEN]** Create `Modules/Collections/app/Services/PeriodicityScheduleResolver.php` implementing `runsForToday(string $periodicityId, Carbon $today, int $generationDay): array`. Rules per design §4: clamp `$generationDay` to 1–28 for MONTHLY/BIMONTHLY/YEARLY. EoM: `$today->day === $today->copy()->endOfMonth()->day`. BIWEEKLY: cycle=1 on day 15, cycle=2 on EoM.
